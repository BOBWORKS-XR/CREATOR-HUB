# Creator Hub 0.1.0-alpha.5

Windows test release for the Project Setup diagnostics update.

## What Is New

- Supports Project Setup 0.3.0-alpha.2 inside Hub, with clearer setup failures
  and versioned local reports to help diagnose problems.
- Explains when an app needs updating before it can open inside Hub. Your usual
  separate app window remains available.
- Keeps the recent-project sorting, alphabetical option and clearer guidance
  for MCP connections that are still running during an update.
- Creator Works MCP 2.7.0-alpha.1 is unchanged. No bridge or Unity-project update
  is needed for this Hub hotfix.

## Updating

1. Leave **Include prereleases** enabled in Hub and choose **Check for updates**.
2. Update Creator Hub first, then choose **Update app** on Project Setup.
3. Save work before approving an installation. If an app is still in use, finish
   the work and close or disconnect it, then choose **Check again**.

Do not uninstall MCP just to close a connection. Hub does not force-close your
AI tools or Unity. Installation still needs your approval; downloading is not
permission to install. Both tools remain usable independently.

Setup reports stay local and sharing them is optional. Review files for personal
information before sharing; do not post full raw logs publicly. The Setup release
includes REPORTING.md with guidance.

## Tested Scope

The exact installer passed Windows packaging and installation checks, including
upgrades from Hub alpha.3 and alpha.4. Three native test paths passed: fresh
install, older MCP/Setup upgrades, and MCP-only use. Tests checked actual hosted
controls, update refusal while a private runtime remained active, cooperative
exit, preserved test settings/project selection and separate app close handling.

The pre-publication Setup test used its exact installer and real signed
descriptor in an isolated test cache. Native security checks were unchanged;
this is not a public-feed download test. MCP used its existing public release.
See the accompanying reports and the [native acceptance run](https://github.com/BOBWORKS-XR/CREATOR-HUB/actions/runs/34590430861).
The [build run](https://github.com/BOBWORKS-XR/CREATOR-HUB/actions/runs/34589242223)
passed its build/install job; its first downstream attempt could not access a
draft download. The test-only correction reused the same installer.

A full signed in-app Hub self-update/restart, historical MSI/BANTWORKS migration,
in-flight MCP shutdown, Unity creation/repair, network completion and headset
behaviour are not confirmed by these tests.

The installer is still unsigned for Windows SmartScreen/Authenticode. Signed
update metadata, the updater signature and SHA-256 checksums are provided; those
are different from Windows publisher signing. This is a prerelease, not stable.

## Public Download Acceptance

After publication, [native acceptance run 34591146264](https://github.com/BOBWORKS-XR/CREATOR-HUB/actions/runs/34591146264) passed all three Windows paths again using the same Hub installer, staging disabled and the public signed app releases. The MCP-only path left Project Setup uninstalled. All 19 Hub and 11 Setup public assets independently matched the reviewed files; signature and tamper checks passed.

This adds public-download evidence, not proof of the full Hub self-update/restart route or Unity project creation. The published installers, reports and checksums have not been replaced.
