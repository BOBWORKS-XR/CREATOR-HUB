# Creator Hub 0.1.0-alpha.3

Windows test release for Creator Works MCP and Creator Project Setup.

## Already Use MCP?

Install Hub first. You do not need to download a separate MCP prerelease or
install Project Setup.

1. Close any older Hub preview and run `Creator-Hub-0.1.0-alpha.3-Windows-setup.exe`.
2. Leave **Include prereleases** enabled, then check for updates.
3. Open the MCP page and choose **Update app**. Approve the installation and
   close MCP clients if prompted. Your settings and project list stay with MCP.
4. Choose **Open hosted development preview**, then **Enable MCP controls** to
   use MCP inside Hub. **Open app** still opens its normal separate window.

New users can choose **Install app** instead. Project Setup is optional and
can be installed or updated from its own Hub page.

## What This Preview Adds

- In-app downloads and upgrades for the reviewed MCP and Project Setup releases.
- Normal MCP controls inside Hub, using the installed app's existing settings.
- Project Setup inside the same window, with its form retained while switching views.
- Verified downloads, installation consent, progress and clear failure messages.
- Guards against updating busy apps and closing Hub during an active operation.
- Hub update checks and a signed update feed. Downloading does not install an update.
- Original dependency notices and a package inventory alongside the installer.

Tested companion releases: MCP **2.7.0-alpha.1** and Project Setup **0.3.0-alpha.1**.

## Important Limits

- This is a **prerelease**, not a stable release. Windows x64 only.
- The installer is **not Windows publisher-signed**. Windows may show an Unknown
  Publisher or SmartScreen warning. Signed Hub metadata and SHA-256 checksums are
  separate from Windows code signing.
- Older BANTWORKS, MSI, duplicate or custom-folder installations may need attention.
  Hub does not silently remove or overwrite unknown copies.
- Automatic shortcut adoption and transfer of an already-open app are not included.
- Older Hub previews need this installer once. A complete in-app Hub upgrade to a
  later signed version has **not yet been tested**; do not treat update-feed
  verification as restart acceptance.
- The native tests do not create a Unity project or prove SDK, headset or multiplayer
  behavior. Test those in your own project after explicitly updating its bridge.

The installer is the exact GitHub-built artifact, not a rebuild of the release tag.
Attached acceptance reports and `release-verification.json` describe the checks
and their scope. Standalone MCP and Project Setup remain available without Hub.
