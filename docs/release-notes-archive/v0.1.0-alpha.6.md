# Creator Hub 0.1.0-alpha.6

Windows prerelease, paired with **Creator Project Setup 0.3.0-alpha.6**.
Creator Works MCP remains on **2.7.0-alpha.1**; no MCP reinstall or new Unity
bridge is required if you already use that version.

## What's Improved

- See Setup's requirements checks and download progress inside Hub.
- Switch between Hub views while Setup works without losing the next progress stage.
- The matching Project Setup shows download size and transfer rate where available,
  and refreshes its requirements after checks and project creation.
- Keep your existing MCP settings. Projects still open newest-first, with A-Z
  sorting available.
- If an existing connection blocks an update, Hub identifies it and offers
  **Check again**. It does not force-close Unity or your AI app.

## Update

1. Save your work and close Creator Hub normally.
2. Run **Creator-Hub-0.1.0-alpha.6-Windows-setup.exe** below.
3. Open Hub, keep **Include prereleases** enabled, and update Project Setup there
   if you use it. Update Hub first: Setup alpha.6 needs this matching version to
   open inside Hub.

Project Setup is optional. Already on MCP 2.7.0-alpha.1? Keep it. An older
recognized MCP can be updated from Hub's MCP page. You do not need to uninstall
just to close an existing AI connection. Save your work, close the identified app
normally, and use **Check again**. Do not end unfamiliar processes.

Hub downloads updates in the app, but installation always requires your approval.
Standalone app windows remain available. This installer only updates Hub; it
does not change Unity projects, bridges or AI configuration.

## Before You Test

- This is a prerelease, not the stable release.
- Windows may show an unsigned-publisher warning. Signed update metadata and
  SHA-256 checksums are included; the installer is not Authenticode-signed.
- Clean-install and upgrade tests use disposable Windows runners and synthetic
  settings. They do not establish every existing user's migration path.
- The complete in-app Hub self-update/restart route is not yet verified. The
  versioned installer is the tested update route.
- One earlier local test-runner failure left a completed Setup process behind.
  Normal app close passed, but recovery from forced or abnormal shutdown is not
  established. Avoid force-closing Hub during setup and report any leftover
  process together with the error shown.
- Unity sign-in/licensing, historical MSI/BANTWORKS installs, custom install
  locations, headset behaviour and macOS/Linux need separate testing.

Please include the app versions, what you tried and the message shown when
reporting a problem. Sharing diagnostic files is optional.

## Verification

Clean-machine Project Setup testing passed actual Unity prerequisite installation,
cancellation, reuse and missing-JDK repair. Unity account sign-in, license
activation and project creation were not part of that test.

The release's JSON acceptance reports record the exact tested installer and
installed executable hashes, CI runs, tested flows and remaining limits.
They distinguish staged Setup testing from public-download testing; no
Unity project-creation or headset result is inferred from install checks.
